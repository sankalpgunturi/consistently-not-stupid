# Gaps

Choices filled in so the desk could run. Argue with these after the flight. None of them are a promise that the book makes money.

- **Research does not gate paper entries.** The user explicitly removed the historical-evidence requirement from the ten-minute paper experiment. The first structurally eligible quote per event is still followed to its official outcome for retrospective analysis. These observations are not fills or ledger profit, and distinct events may share risks. Minimum sample size, Wilson confidence bounds and historical edge do not block entries. Legacy replay (`entry_window_minutes=0`) retains its original historical rule. Probability, timing, fees, liquidity, stability, exposure limits and executable depth still apply.
- **Live trading is a capped switch.** The dashboard asks for a whole-dollar amount from $1 to $5,000 and, on approve, signs orders with the `.env` key. The amount is a cap, not a deposit. A lost response after Kalshi accepts an order can leave an exchange fill out of the local book until the next restart is reconciled by hand. Reset is refused while live. An open clip from a venue this desk no longer reads, including an older Polymarket fill, is closed at cost when the book opens and the cash is returned.
- **The Decisions drop threshold is 0.6.** A clip is removed only when the matching answer is `drop` and the probability on `drop` is at least 0.6. Below that, or on any bad body, the deterministic set stands. The model cannot add a market.
- **Operator controls take precedence.** The dashboard permits entry probability from 80–99%, outcome window from 1–60 minutes, scan interval from 1–60 seconds, amount per bet from $1–$100, and the timed probability stop. Automatic reviews may suggest changes but cannot apply changes to these controls in short-window mode. Other automatic changes remain one step tighter inside the rails.
- **No login.** The owner explicitly requested that anyone with the permanent Cloudflare dashboard URL have the same controls. The Worker checks its own CSRF token and rejects foreign origins; a secret-authenticated publisher relays commands to RC Personal, where persistent command IDs prevent replay. The engine runs on `chitti-rc-personal` under systemd. The local desk requires a separate CSRF token. `Origin` and `Host` have to be localhost or the host passed to `--host`, including on the state read and the snapshot socket. An IPv6 bind is the full address, with or without brackets. A wildcard bind such as `0.0.0.0` trusts only loopback names. That is not an account system.
- **Fees use the series multiplier and round up to the next cent.** Each scan reads the public series metadata for favorites. Unknown schedules block admission. Exit marks retain the entry fee schedule. Account-specific precision, later fee changes on an open position, and per-order rounding rebates are not simulated.
- **The scan is not the whole venue.** Near-term discovery prioritizes the next ten minutes, then the next hour and day, plus an unfiltered open-market allocation. With eight market-list requests, it reserves one per broader window and can spend five on 1,000-market pages nearest-first. Unused requests pass to later windows; a warning records when the nearest window still has more pages at its cap. These close-time discovery windows do not replace the explicit expected-outcome check at admission.
- **Paper entries hold to the official result.** The user removed automatic stop-loss exits. Price declines change the mark but do not sell the position. The operator may still close manually. Legacy replay retains its stop rule.
- **Ten minutes is the outcome window, not the scan interval.** Background quote monitoring and evaluation target one-second cadence, with bounded discovery on a five-second target (longer when API reads take longer). A shared public-read ceiling and adaptive throttling constrain API traffic. Model review and fill checks can delay admission while quote monitoring continues; positions are also marked between scans. Quotes and entry timing are checked again before a fill. An unchanged book gets routine model commentary at most once every ten minutes; proposed buys and changed review inputs trigger review sooner. Deterministic screening continues each scan.
- **Settlement waits for Kalshi `result`.** A clip settles when `result` is `yes` or `no`. A price near 0 or 1 does not settle it. If the flag is missing, the position stays open. A settled payload that omits the bid and the ask still settles from the winner.
- **A person cannot force a buy** the fee rule, the horizon, or the depth check refused.
- **Paper size is the displayed touch.** Kalshi publishes bids, so the other side's bids are the ask. An unfamiliar payload is a refusal, not a fill.

## Repository review, October 7, 2026

Fixed: background scans no longer build discarded dashboard snapshots; the publisher requests a compact response without research archives; archived market URLs use an indexed lookup scoped to the active ledger. Partial sales now retain the unsold position and allocate its cost basis atomically. Removed unused imports, an unused proposal list, and the unreferenced `horizon_end` helper. Legacy replay, simulations, migrations, and Mac recovery scripts remain used or documented interfaces.

Remaining findings:

- Live order acceptance and local accounting are not reconciled automatically after a lost response or process crash. A persistent order journal and venue-fill reconciliation are needed before reliable unattended live operation. No live orders were used for this review.
- Live accounting estimates fees rather than recording the exchange's actual fill fees. Partial-sale ledger accounting is fixed, but the dashboard still assumes one entry and one closing event per trade; partial closes need a richer trade grouping model.
- Model vetoes and reviews are sequential admission work. They can consume seconds per proposal batch even though quote monitoring and open-position checks continue. Making them asynchronous requires expiration and portfolio-version checks; skipping them would change the strategy.
- Trade history and research storage grow without bound. The dashboard initially shows five trades but transfers the full trade history. Server-side pagination and archival are future scaling work; no history was deleted.
